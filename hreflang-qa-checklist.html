Hreflang QA checklist before localized pages launch

Use this checklist before multilingual or multi-market pages go live. It focuses on mistakes that can be caught from pasted URL maps and HTML head snippets without crawling or Search Console access.

1. Confirm every localized group has all variants

  • List each page group, language or region code, localized URL, and canonical URL.
  • Include every intended language variant for the group.
  • Mark any neutral fallback URL as `x-default`.

2. Check self-referencing alternates

  • Each localized page should list itself as an alternate.
  • The self-reference should use the same absolute URL that the page serves.
  • Use one clear code per URL to avoid duplicate language assignments.

3. Check reciprocal links

  • If the English page lists the French page, the French page should list the English page back.
  • Repeat the check across every variant in the page group.
  • Do not rely on only a language selector or sitemap if page-level tags are incomplete.

4. Check canonical conflicts

  • A localized page should not accidentally canonicalize to another language page.
  • Review templates where all translated pages inherit the same canonical URL.
  • Keep deliberate consolidation documented so the launch team knows it is intentional.

5. Check URL and code hygiene

  • Use fully-qualified URLs in alternate and canonical tags.
  • Review invalid or inconsistent language and region codes.
  • Look for duplicate hreflang codes in the same snippet or page group.

6. Prepare the handoff

  • Summarize missing self-references, reciprocal gaps, canonical conflicts, invalid codes, and relative URLs.
  • Assign fixes to the SEO, content, or development owner before launch.
  • Retest the final templates or pasted snippets after fixes are applied.
